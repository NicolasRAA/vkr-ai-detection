# Проектный семинар и ВКР

Репозиторий для материалов проекта в седьмом и восьмом семестрах. Каждый этап сдаётся через pull request (PR). Исправления добавляются в тот же PR; после принятия работы преподавателем семинара его объединяют с `main`.

## Начать работу

1. Создайте репозиторий через **Use this template → Create a new repository**. Выберите **Public**, не включайте **Include all branches**. Для общего проекта достаточно одного репозитория команды.
2. Укажите тему и участников проекта внизу этой страницы.
3. В таблице курса каждый студент указывает свой GitHub username, репозиторий и ссылку на PR при сдаче этапа.
4. Прочитайте [порядок сдачи](course/submission.md) и [задания со сроками](course/assignments.md).

Условия лабораторных хранятся на Google Диске. На GitHub — шаблоны отчётов и пояснения, куда загрузить результаты:

- **ЛР 2:** [условия](https://docs.google.com/document/d/1AUkfCrnECeBZ_7J4OcKBxSRCcol2ODT-/edit) · [папка и сдача](course/lab2.md) · [шаблон `docs/research/report.md`](docs/research/report.md).
- **ЛР 3:** [условия](https://docs.google.com/document/d/1eUcNd1wMwoVaSu-DSS-cVRgLJvTT6vza/edit) · [папка и сдача](course/lab3.md) · [шаблон `docs/design/report.md`](docs/design/report.md).

## Формат и структура

**Предпочтительный формат лабораторных — Markdown (`.md`).** DOCX и PDF также допускаются. Презентации — PPTX или PDF. Требования к оформлению итогового отчёта указаны в заданиях курса.

| Папка | Материалы |
|---|---|
| [docs/research/](docs/research/) | Тема, источники, аналоги, цель и задачи |
| [docs/requirements/](docs/requirements/) | Техническое задание и требования |
| [docs/design/](docs/design/) | Модели, диаграммы и архитектура |
| [docs/implementation/](docs/implementation/) | Реализация, запуск и проверка результата |
| [docs/results/](docs/results/) | Итоговый отчёт, материалы ВКР и выбранного варианта восьмого семестра |
| [assets/](assets/) | Изображения и диаграммы |
| [src/](src/) | Исходный код |

Инструкции находятся в `course/`, ваши документы — в `docs/`. Структуру можно менять под проект; папки по номерам лабораторных не нужны.

## Проект

**Тема:** Система обнаружения изображений и видео, созданных генеративными моделями: серверная часть с моделью ИИ и мобильное приложение.

**Участники:**

- Олойеде Джибрил (К3420) – ВКР «Разработка мобильного приложения для обнаружения ИИ-сгенерированных изображений и видео с интеграцией ансамблевых сервисов глубокого обучения»: мобильное приложение и его связь с сервером
- Арройо Николас (К3420) – ВКР «Разработка нейросетевой архитектуры и серверного API для классификации изображений и видео по признакам искусственной генерации»: модуль ИИ, серверный API, анализ видео.
  
**Проблема:** Сгенерированное изображение на глаз уже трудно отличить от фотографии: в эксперименте Microsoft участники ответили верно лишь в 62 % случаев. Детекторы, обученные на изображениях прошлых генеративных моделей, на новых теряют точность, а маркировку ставят далеко не все. Готовые сервисы проверки платные сверх небольших лимитов и получают изображения пользователей на свои серверы.

**Ожидаемый результат:** Мобильное приложение отправляет изображение или видео на сервер проекта и показывает ответ: реальное оно или сгенерированное, с какой уверенностью и какая модель приняла решение. На сервере маршрутизатор по содержанию изображения выбирает экспертную модель, а если не уверен – общую.
