# ЛР 2 - обоснование актуальности ВКР

**Тема ВКР:** «Разработка мобильного приложения для обнаружения ИИ-сгенерированных изображений и видео с интеграцией ансамблевых сервисов глубокого обучения» (Джибрил).

Автор: Олойеде Джибрил, группа К3420

Связанная тема второго участника команды: «Разработка нейросетевой архитектуры и серверного API для классификации изображений и видео по признакам искусственной генерации» (Николас).

**Вклад каждого участника при командной работе:**

- **Джибрил**: обзор прямых и косвенных аналогов (мобильные приложения, веб-сервисы, B2B-решения), таблица сравнения, требования к клиентской части. Поиск источников по мобильному инференсу и практическим сервисам. Разделы 3 и 4 (актуальность, задачи клиентской части).
- **Николас**: обзор научных работ по архитектурам детекторов (GAN/диффузия, видео), обзор датасетов и бенчмарков, требования к серверному API и ансамблю моделей. Разделы 2 и 4 (датасеты, задачи серверной части).
- **Совместно**: формулировка цели, общая архитектура системы «мобильный клиент ↔ серверный API ↔ ансамбль моделей», выводы.

### Выводы по обзору

1. **Подходы.** Выделяются три семейства детекторов: (а) CNN-классификаторы, обученные с аугментациями сжатия и размытия [1, 3]; (б) модели на признаках больших предобученных энкодеров (CLIP) [2]; (в) детекторы низкоуровневых артефактов генерации (NPR, частотные отпечатки) [3, 7]. Для видео используются покадровый анализ и пространственно-временные модели [4, 5, 9].
2. **Ансамбли.** Ансамбли разнородных моделей стабильно лучше одиночных моделей на смешанных типах подделок [5, 12, 13], но состав и способ агрегации нужно подбирать экспериментально [12]. Открытые платформы с несколькими детекторами уже есть [10], но они веб-ориентированы и рассчитаны на исследователей.
3. **Нерешённые вопросы.**
   - Обобщение на новые генераторы: детекторы, обученные на GAN, теряют качество на диффузионных моделях [3, 6].
   - Устойчивость к пережатию и масштабированию, которые неизбежны при пересылке через мессенджеры [1, 3, 17].
   - Понятное объяснение результата неспециалисту (вероятность, вклад каждой модели, тепловая карта) [8, 10].
   - Почти полное отсутствие мобильных клиентов, которые объединяют несколько моделей и работают с русскоязычной аудиторией и отечественными генераторами (Kandinsky, Шедеврум, GigaChat).
4. **Значимость.** Число дипфейков и ущерб от них растут, а маркировка контента не решает проблему полностью [14–16]. Нужны независимые и доступные инструменты проверки.

## 3. Обзор и сравнение аналогов

### Прямые аналоги

- **Deepware Scanner** (https://deepware.ai/) — бесплатный сервис проверки видео на дипфейки, есть веб-интерфейс и мобильные приложения. *Ограничения:* ориентирован на лица, слабо работает с полностью сгенерированными сценами и современными диффузионными видео, проверяет по одному файлу, мало объясняет результат.
- **AI or Not** (https://www.aiornot.com/) — веб-сервис и API для обнаружения ИИ-изображений, видео и аудио. *Ограничения:* закрытая модель без объяснения решения, бесплатный режим ограничен, нет русского интерфейса. Результат — одна оценка без разбивки по моделям.
- **Hive AI-Generated Content Detection** (https://thehive.ai/) — коммерческий API и расширение для браузера, определяет вероятный генератор (Midjourney, DALL·E, Stable Diffusion и др.). *Ограничения:* B2B-модель и оплата API, нет полноценного мобильного приложения для конечного пользователя, закрытые модели.
- **DeepFake-o-meter** (https://deepfake-o-meter.ai/) — открытая академическая платформа Университета Буффало: файл проверяется несколькими опубликованными детекторами, показываются результаты каждого [10]. *Ограничения:* только веб, интерфейс для исследователей, очередь обработки, нет мобильного клиента и сводного вердикта для неспециалиста.
- **TrueMedia.org** (https://www.truemedia.org/) — некоммерческий сервис, объединявший шесть собственных детекторов и модели партнёров для проверки политических дипфейков. *Ограничения:* закрыт в январе 2025 г. из-за стоимости поддержки, код открыт. Возрождается Джорджтаунским университетом, доступность нестабильна, мобильного приложения нет.
- **Мобильные приложения App Store / Google Play** («AI Detector — Detect AI Image», «Fake or Not», «TruthLens», VerifyLabs.AI и др.). *Ограничения:* как правило, используют одну закрытую модель или сторонний API, не раскрывают метод и точность, часто работают по платной подписке.

### Косвенные аналоги

- **Google SynthID Detector / проверка в приложении Gemini** (https://deepmind.google/models/synthid/) — проверяет наличие невидимого водяного знака SynthID. *Ограничения:* надёжно распознаёт только контент моделей Google и ничего не говорит о контенте других генераторов.
- **C2PA / Content Credentials** (https://contentcredentials.org/verify) — проверка криптографически подписанных метаданных о происхождении файла. *Ограничения:* метаданные теряются при пересылке через мессенджеры и соцсети, большинство генераторов их не добавляют.
- **Intel FakeCatcher** (https://www.intel.com/) — обнаружение дипфейк-видео по сигналам кровотока на лице (фотоплетизмография). *Ограничения:* работает только с видео, где видно лицо, корпоративный продукт.
- **VisionLabs Deepfake Detection, MWS AI, «Контур.Толк»** — российские B2B-решения для банковского KYC, медиа и видеоконференций. *Ограничения:* недоступны частным пользователям, решают задачу верификации личности или мониторинга, а не проверки произвольного файла.
- **Reality Defender** (https://www.realitydefender.com/) — мультимодальная корпоративная платформа с API и плагинами для Zoom/Teams. *Ограничения:* ориентация на бизнес, непрозрачные цены, бесплатный лимит небольшой.
- **FotoForensics** (https://fotoforensics.com/) — анализ уровня ошибок JPEG (ELA) и метаданных. *Ограничения:* классический криминалистический метод, требует экспертной интерпретации, не предназначен для ИИ-генерации.

### Выводы по сравнению

Что можно использовать:

- Идею запуска нескольких опубликованных детекторов и показа их результатов (DeepFake-o-meter, TrueMedia).
- Определение вероятного генератора (Hive).
- Мобильный сценарий «загрузил — получил ответ» (Deepware и приложения из магазинов).
- Проверку водяных знаков и метаданных происхождения (SynthID, C2PA) как дополнительный сигнал, а не основной метод.

Какие ограничения мы устраняем:

1. Нет мобильного клиента, который объединяет несколько моделей. Существующие ансамблевые решения работают только в браузере, а мобильные приложения используют одну закрытую модель.
2. Результат не объясняется: вместо одной цифры пользователь видит сводный вердикт, вклад каждой модели, тепловую карту подозрительных областей и проверку метаданных.
3. Неудобный импорт: файлы из мессенджеров можно отправить через «Поделиться», а при подготовке и оценке учитывается их пережатие.
4. Нет работы офлайн: лёгкая модель на устройстве даёт быструю предварительную оценку, полная проверка выполняется на сервере (API из работы Николаса).
5. Нет локализации: русский интерфейс и тестирование на изображениях отечественных генераторов.

## 4. Итоги

**Итоговая тема ВКР:** «Разработка мобильного приложения для обнаружения ИИ-сгенерированных изображений и видео с интеграцией ансамблевых сервисов глубокого обучения» (тема остаётся без изменений).

**УДК для тезиса:** 004.932:004.42 (распознавание и обработка изображений; программирование, разработка приложений).

**Ключевые слова:** ИИ-сгенерированный контент, дипфейк, обнаружение синтетических изображений, обнаружение сгенерированного видео, ансамбль моделей, глубокое обучение, мобильное приложение, диффузионные модели, объяснимость, Grad-CAM, REST API.

### Актуальность исследования

Генеративные модели (Midjourney, Stable Diffusion, DALL·E, Sora, Kandinsky и др.) за последние годы стали массовыми, и их результаты всё труднее отличить от реальных фото и видео. Дипфейки используются в мошенничестве, политических манипуляциях и дезинформации [15, 16]. В России число случаев мошенничества с дипфейками в первой половине 2025 г. выросло примерно в 2,3 раза к аналогичному периоду 2024 г. (исследование Ростелекома, ФРИИ и ИРИ, по данным ComNews, 2026). Крупные компании (Сбер, МТС/VisionLabs, MWS AI, СКБ «Контур») уже развивают собственные детекторы, но для бизнеса, а не для частных пользователей.

Научные работы показывают, что одиночные детекторы плохо обобщаются на новые генераторы, особенно диффузионные [3, 6], и теряют качество на пережатых файлах [1, 3]. Ансамбли разнородных моделей заметно повышают устойчивость [5, 12, 13]. При этом существующие ансамблевые платформы (DeepFake-o-meter, TrueMedia) доступны только через браузер, ориентированы на исследователей или закрыты. Мобильные приложения используют одну закрытую модель без объяснения результата. Водяные знаки (SynthID) и метаданные C2PA покрывают лишь часть генераторов и теряются при пересылке.

Большая часть сомнительного контента приходит к пользователю на смартфон через мессенджеры и соцсети. Поэтому сейчас востребовано доступное мобильное приложение, которое объединяет ансамбль моделей на сервере, быструю локальную проверку и понятное объяснение результата.

### Цель исследования

Разработать мобильное приложение для обнаружения ИИ-сгенерированных изображений и видео. Приложение должно отправлять файл в серверный ансамбль моделей глубокого обучения, выполнять предварительную проверку на устройстве и показывать пользователю объяснимый результат.

### Задачи исследования

**Задачи по теме Джибрила (мобильное приложение):**

1. Проанализировать существующие решения и сформулировать функциональные и нефункциональные требования к мобильному приложению: типы файлов, время ответа, приватность, офлайн-режим.
2. Спроектировать архитектуру клиент-серверной системы и протокол взаимодействия с серверным API (совместно с Николасом): загрузка файлов, асинхронная обработка видео, формат ответа ансамбля.
3. Выбрать технологический стек кроссплатформенного мобильного приложения (Android/iOS) и среду выполнения моделей на устройстве (LiteRT/TensorFlow Lite или ONNX Runtime Mobile).
4. Реализовать модуль предварительной проверки на устройстве на базе лёгкой модели (MobileNetV2 / EfficientNet-Lite / NPR) и проверку метаданных (EXIF, C2PA).
5. Реализовать интерфейс: загрузка из галереи и камеры, импорт через «Поделиться», отображение сводного вердикта, вклада каждой модели и тепловой карты Grad-CAM, история проверок.
6. Провести тестирование: точность на тестовых выборках (в том числе на пережатых через мессенджеры файлах), время отклика, нагрузка на устройство, юзабилити-тестирование. Сравнить с аналогами (AI or Not, Hive, Deepware).

**Задачи по теме Николаса (модели и серверный API):**

1. Сформировать обучающие и тестовые выборки из открытых датасетов и собственной выборки изображений отечественных генераторов.
2. Обучить и сравнить кандидатов в ансамбль (CNN с аугментациями, CLIP-детектор, NPR, видеомодель), подобрать состав и способ агрегации.
3. Разработать серверное REST API для классификации изображений и видео с выдачей оценок каждой модели и карт внимания.
