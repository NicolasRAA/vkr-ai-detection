# ЛР 2 – обоснование актуальности ВКР

**Тема ВКР:** Разработка нейросетевой архитектуры и серверного API для классификации изображений и видео по признакам искусственной генерации

**Автор:** Арройо Николас, группа К3420

**Вклад участников:** работа индивидуальная. ВКР входит в совместный проект: мобильное приложение для проверки изображений и видео разрабатывает другой студент в своей ВКР. Здесь рассматривается только серверная часть – нейросетевая архитектура (модуль ИИ), серверный API и модуль анализа видео.

### Выводы по обзору

В литературе встречаются четыре подхода. Чаще всего обучают один классификатор на CNN или трансформере; такие детекторы хорошо работают на генеративных моделях из обучающей выборки, а на новых теряют точность: 58 % в среднем на VCT² [2], 31–43 % у AIDE и Effort на Mirage-Test [3], 0,5803 у детектора [11] на подделках другого типа. Второй подход ищет следы генерации в шуме и спектре изображения [6; 10; 11]. Третий объединяет несколько моделей в ансамбль [4; 12; 13], и в NTIRE 2026 так устроено большинство финальных решений [4]. Четвёртый, самый новый, распределяет изображения между семантическими экспертами; из рассмотренных работ так делает только OmniAID [3].

Нерешёнными остаются обобщение на генеративные модели, которых не было в обучении [2–4], зависимость точности от содержания изображения [1; 3; 8] и устойчивость к сжатию и уменьшению [4; 5]. Лучшие решения NTIRE 2026 и OmniAID требуют ресурсов, которых у студенческой работы нет: OmniAID обучался на четырёх GPU H200 [3]. В OmniAID эксперты встроены в одну сеть, маршрутизатор обучается вместе с ними, и для новой области нужно обучить эксперта и обновить маршрутизатор. Работы, где маршрутизатор из готовых предобученных моделей отправлял бы изображение одной из независимых экспертных моделей, а при неуверенности – общей модели, среди рассмотренных нет.

## 3. Обзор и сравнение аналогов

### Прямые аналоги

Сервисы, которые по запросу классифицируют изображение (у части – и видео) как реальное или сгенерированное.

- **Hive** ([документация](https://docs.thehive.ai/docs/ai-image-and-video-detection), [цены](https://thehive.ai/pricing)). API с двумя моделями: для сгенерированных изображений и для дипфейков. Указывает вероятную модель-источник из 97 классов и передаёт метаданные C2PA, если они есть; видео рекомендуется считать сгенерированным, если хотя бы один кадр получил оценку 0,9. Ограничения: методика закрыта, точность на страницах сервиса не указана, 6 долларов за 1 000 изображений, изображения уходят поставщику.
- **Sightengine** ([цены](https://sightengine.com/pricing), [статья разработчика](https://sightengine.com/per-generator-ai-detection-granularity)). API с оценкой по 24 генеративным моделям, видео с частотой от 0,5 до 2 кадров в секунду на платных тарифах. Ограничения: бесплатно 2 000 операций в месяц и без видео; заявленные 98,3 % – цифра разработчика, а в исследовании ARIA на одном подмножестве сервис распознал 25,12 % изображений [7].
- **AI or Not** ([цены](https://aiornot.com/pricing)). Изображения, видео, аудио и текст, ключ API на бесплатном тарифе. Ограничения: бесплатно 20 проверок изображений, точность на странице тарифов не указана.
- **Reality Defender** ([объявление о бесплатном API](https://realitydefender.com/insights/reality-defender-launches-free-access-to-deepfake-detection-api)). API и SDK, несколько моделей, анализ изображения целиком. Ограничения: 50 проверок в месяц бесплатно, на момент запуска API видео не поддерживалось.
- **Детектор РВБ** ([сайт](https://aidetector.rwb.ru/), [новость](https://www.sostav.ru/publication/wildberries-zapustil-detektor-dipfejkov-79503.html)). Бесплатный веб-сервис, 100 проверок в месяц, форматы JPG, PNG и WebP. Ограничения: только изображения, API в публикациях не описан, точность 95 % – по заявлению компании.
- **KodikScan** ([новость](https://www.anti-malware.ru/news/2026-05-25-111332/50147)). Бесплатный веб-сервис для изображений, видео, аудио и текста. Ограничения: методика не описана, 98,03 % – по данным разработчика, который сам советует считать результат подсказкой.

### Косвенные аналоги

Решения, которые решают часть задачи или решают её другим способом.

- **SynthID Detector, Google** ([блог Google](https://blog.google/technology/ai/google-synthid-ai-content-detector/)). Ищет водяной знак SynthID, который ставят инструменты Google. Ограничение: материалы без этого знака не распознаёт.
- **OmniAID** ([arXiv](https://arxiv.org/abs/2511.08423v4)). Исследовательский детектор с семантическими экспертами и универсальным экспертом [3], код открыт (MIT). Ограничения: эксперты и маршрутизатор – части одной сети, набор областей фиксирован, маршрутизатор всегда выбирает экспертов и не передаёт изображение общей модели, 508,78 млн параметров, сервиса нет.
- **Ансамбли NTIRE 2026: MICV, Ant International, HEDGE, PRISM** ([отчёт](https://arxiv.org/abs/2604.11487v1)). Лучшие решения соревнования, AUC ROC на искажённых изображениях до 0,9723 [4]. Ограничения: каждое изображение обрабатывают все модели ансамбля; у решения второго места 14 млрд параметров и 78,25 ГБ видеопамяти.
- **«Алетейя», Сбер** ([новость](https://www.anti-malware.ru/news/2025-10-29-111332/47875)). Выявление подделок в видео и аудио, работает с несколькими лицами в кадре. Ограничения: публичного доступа нет, изображения не обрабатывает.
- **TrueMedia.org** ([открытый код](https://www.truemedia.org/post/open-source-release)). Некоммерческий сервис проверки изображений, видео и аудио, закрыт в январе 2025 года; детекторы и веб-приложение опубликованы под лицензией MIT. Ограничения: сервис не поддерживается.

### Таблица сравнения

**Почему выбраны эти критерии.** Система – сервер, к которому обращается мобильное приложение. Отсюда критерии доступа (есть ли API) и стоимости запроса. Пользователи отправляют личные фото, поэтому важно, где обрабатываются изображения. По обзору литературы точность сильно зависит от содержания изображения и от генеративной модели, поэтому сравнивается, кто заявляет точность и есть ли она по категориям. Новые генеративные модели появляются каждый год, поэтому учитывается модульность – можно ли добавить или заменить детектор без переобучения остального. Последний критерий – вычислительные ресурсы, так как работа ведётся на бесплатной платформе Kaggle.

### Выводы по сравнению

Из существующих решений берутся три идеи. Видео, как у Hive и Sightengine, анализируется по отдельным кадрам. Из OmniAID – разделение на семантических экспертов и его тестовый набор Mirage-Test, на котором уже опубликованы результаты других детекторов. Из NTIRE 2026 и работы [5] – проверка на искажённых изображениях.

Устранить предполагается такие ограничения. Коммерческие сервисы дают одну цифру точности, чаще всего по заявлению разработчика; в ВКР точность измеряется по категориям и генеративным моделям на открытых тестовых наборах. Сервисы берут плату сверх небольших бесплатных лимитов и получают изображения пользователей; система работает на собственном сервере. OmniAID и лучшие ансамбли NTIRE 2026 требуют многих GPU; система обучается на одной T4. В OmniAID новая область требует переобучения маршрутизатора, а маршрутизатор ВКР собран из готовых YOLO и CLIP и не обучается, поэтому экспертную модель можно добавить или заменить отдельно. Если маршрутизатор не уверен, изображение получает общая модель.

Указание конкретной генеративной модели, как у Hive и Sightengine, а также аудио и текст в работу не входят.

## 4. Итоги

**Итоговая тема ВКР:** Разработка нейросетевой архитектуры и серверного API для классификации изображений и видео по признакам искусственной генерации (без изменений).

**УДК для тезиса:** 004.932.2

**Ключевые слова:** обнаружение сгенерированных изображений, генеративные модели, глубокое обучение, экспертные модели, семантическая маршрутизация, YOLO, CLIP, EfficientNet, ключевые кадры видео, серверный API.

### Актуальность исследования

Люди плохо отличают сгенерированные изображения от фотографий: 62 % верных ответов в эксперименте Microsoft [1] и 65,24 % в исследовании ARIA [7]. Детекторы тоже отстают. Семнадцать опубликованных детекторов на наборе VCT² показали в среднем 58 % [2], а AIDE и Effort, обученные на изображениях Stable Diffusion v1.4, на изображениях моделей около 2025 года дали 31,25 и 43,03 % [3]. В соревнование NTIRE 2026 вошли изображения 42 генеративных моделей 2022–2026 годов, и организаторы считают задачу нерешённой [4].

Модель, которую я обучил на производственной практике, показала 91,32 % на тестовой выборке [15], но её обучал на наборе 2023 года без FLUX, Stable Diffusion 3 и Midjourney v6. На изображениях этих моделей её точность, вероятно, ниже; первый эксперимент ВКР это проверит.

Маркировка задачу не снимает. Статья 9 закона № 243-ФЗ вступает в силу 1 марта 2027 года и оставляет предупреждение об использовании ИИ на усмотрение автора материала [14], водяной знак SynthID есть только у материалов инструментов Google, а метаданные удаляются. Нужен анализ самого изображения.

Точность при этом зависит от содержания изображения [1; 3; 8], а коммерческие сервисы публикуют одну цифру и обрабатывают изображения у себя (раздел 3). Мобильному приложению совместного проекта нужен сервер, который можно обновлять по мере выхода новых генеративных моделей, заменяя отдельные экспертные модели, и точность которого известна по каждой категории.

### Цель исследования

Разработать нейросетевую архитектуру из семантического маршрутизатора, экспертных моделей и общей модели и серверный API на её основе, которые классифицируют изображения и видео как реальные или сгенерированные точнее модели, разработанной на практике, прежде всего на изображениях генеративных моделей 2024–2026 годов.

### Задачи исследования

1. Проанализировать аналоги и сформулировать функциональные и нефункциональные требования к серверной системе.
2. Оценить, насколько модель практики теряет точность на изображениях современных генеративных моделей (Mirage-Test, MS COCOAI), отдельно по категориям.
3. Собрать из открытых наборов данных обучающие и тестовые выборки, сбалансированные по классам внутри каждой категории.
4. Разработать двухуровневый маршрутизатор YOLO → CLIP, который при неуверенности передаёт изображение общей модели, и измерить точность маршрутизации.
5. Обучить экспертные модели (первая – для изображений с людьми) и дообучить общую модель на платформе Kaggle.
6. Разработать модуль анализа видео по ключевым кадрам с агрегированием оценок и временной метрикой.
7. Реализовать серверный API на FastAPI с историей проверок в базе данных.
8. Сравнить систему с моделью практики и с контрольной моделью по категориям, с 95-процентными доверительными интервалами и критерием Макнемара, и проверить устойчивость к сжатию JPEG и уменьшению изображений.
